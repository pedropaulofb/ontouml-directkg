There are 22 stored JSON sources: 12 contract-positive cases (including the explicit no-validation-of-omitted-view-IDs case), 9 parseable governed negatives (2 unknown-information cases, 7 duplicate-declaration cases), and 1 intentionally malformed JSON document. Fixture checks verify the named authoring defects, reference/type resolution, binary ends, and the presentation structures used here. They are bounded authoring checks, not a production validator or a compatibility claim for arbitrary schema documents.

The 2 stored Turtle files are **partial ground asserted graphs**. Their exact input/expectation pairing is recorded below, including cross-bundle use of the canonical shared core. Unknown concrete DKGM identity, optional metadata, and unspecified generated-comment wording prevent a whole-output fixture from being normative. Inter-conversion comparisons select fixed domain predicates, retain required source labels/IDs, and permit the stated unordered pairwise disjointness presentation. Serialization round trips and access within the same conversion use whole-graph isomorphism. None of these checks requires an OWL reasoner, textual Turtle order, stable blank-node labels or byte-identical output.

Equivalent cases are grouped deliberately: the complete stereotype table is tested with default tolerant input handling, with selected cells repeated under all input policies to establish precedence. Every-policy repetition is retained for explicit policy-independent fatal/nonfatal guarantees. Ordinary collision suffix allocation is checked as a complete suffix set and repeated source mapping; ID ordering is not invented where the rule leaves it open.
